# 记账 App 竞品调研：记账方式、提醒推送、界面

调研日期：2026-11-21。来源均为公开资料，标注了链接。商业数据（下载量排名）未能直接读取，
"高下载"以各类榜单与媒体评测中反复出现的产品为准。

## 1. 记账方式（按重要性排序）

| 方式 | 代表产品 | 要点 | 来源 |
|---|---|---|---|
| 自动抓取支付结果 | 钱迹、好好记账、AutoAccounting | 无障碍识别支付成功页或读取通知；弹出确认窗口，用户核对金额、分类、账户 | [钱迹 Android 文档](https://docs.qianjiapp.com/auto/qianji_auto_android.html) |
| 极速手动记一笔 | Finny（Quick Log）、记一笔、轻记账 | 强调"每笔几秒"，是否忘记记账是留存的关键 | [Finny 对比文](https://getfinny.app/blog/ynab-vs-copilot-money-2026) |
| 桌面小组件 / 快捷方式直达记账 | Wallet（BudgetBakers）、好好记账 | 小组件里直接输入金额；快捷方式跳过首页 | 搜索摘要（Wallet 社区与评测） |
| 模板与周期账单 | 好好记账 | 房租、订阅等固定支出一次设置，按周期自动生成 | 好好记账 Windows 版介绍 |
| 一句话/语音录入 | 对话式记账类 App | 输入"午饭 28"，自动解析金额、收支、分类 | 博客摘要，证据较弱，仅作参考 |
| 自动分类并学习纠正 | Copilot Money | 你改过一次，它以后就记住；订阅自动识别 | [Finny 对比文](https://getfinny.app/blog/ynab-vs-copilot-money-2026) |

### 钱迹踩过的坑（直接可借鉴）
- 无障碍服务被系统后台杀掉后会失效，文档明确要求用户开启"自启动""忽略电池优化"。我们的引导页已有这两项。
- 微信支付成功页、云闪付详情页会被系统"支付安全检测"拦截弹窗，只能退到后台才显示。我们是后台写库，不弹窗，**不受这个问题影响**。
- 微信发红包后需要再点开红包才能识别。我们的解析器已把红包单独成类，但红包页识别仍是已知缺口。
- 淘宝主动屏蔽无障碍，无解。

## 2. 提醒与推送

- 普遍做法：**一天一次、用户自选时间的记账提醒**，默认关闭。依据：多篇习惯类文章建议"前一周当闹钟用"（[cashflow](https://cashflow.hamzawaleed.com/blog/smart-notifications)），但这是博客观点，未找到大样本数据。
- 通知泛滥会让用户全部关掉，因此提醒应少而准。
- 钱迹把"服务是否在运行"放进通知栏常驻状态，方便用户一眼确认。我们有"监听断开"提醒，但没有常驻状态。

## 3. 界面

- Copilot 被普遍评价为"最好看的记账类 App"，重点在数据可视化和干净的首屏。
- Monarch、YNAB 的共同结构：**首屏是概览 + 最近流水，记账入口醒目**。与我们这次重构的方向一致。
- 高频记账 App 的首屏不放太多图表，图表放在二级统计页。

## 4. 对 AutoLedger 的映射

| 调研发现 | 我们现状 | 建议 | 优先级 |
|---|---|---|---|
| 自动记账可撤销 | 高置信直接入账，无撤销 | 入账通知加"撤销"按钮 | 高 |
| 小组件直达记账 | 小组件只显示数字 | 小组件增加"记一笔"入口，直接打开手动记账 | 高 |
| 一句话录入 | 只有表单 | 手动记账增加一行文本，解析"金额 + 商户"，复用已有的 `parseAmountToCents` 与分类器 | 中 |
| 每日记账提醒 | 没有 | 可选，默认关闭，用户自选时间 | 中 |
| 周期账单 | 没有 | 房租、订阅类，先记入待办 | 低（后续） |
| 通知栏常驻服务状态 | 没有 | 可选，默认关闭 | 低 |
| 首屏概览 + 流水 | 已按此重构账单页 | 保持 | 已完成 |

## 5. 不照搬的部分
- YNAB 的"零基础预算"要求每一块钱先分配，对多数人过重，我们保持"月总预算 + 分类预算"的轻量方案。
- 钱迹的入账前弹窗确认会增加摩擦。我们选择直接入账、可撤销，效率更高。
